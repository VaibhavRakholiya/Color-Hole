# Color Hole

A browser puzzle game in the style of **Catdom: Color Hole**. Drag a coloured hole across
the board; cats of its colour fall in. Clear every cat to finish the level.

No framework, no build step, no dependencies. Plain ES modules and a 2D canvas.

## Running it

```bash
python3 -m http.server 8765
```

Then open <http://localhost:8765>. Any static file server works; it must be served over
HTTP rather than opened as a `file://` URL, because the code uses ES modules and `fetch`.

## Rules

- The board is a grid of **cats** (1×1, static) and **holes** (coloured polyominoes).
- Each hole carries a number: how many cats it can still swallow.
- Drag a hole in any direction. It slides a cell at a time.
- A cat of the **same colour** is swallowed and the counter drops. A cat of any **other**
  colour blocks the hole, as do walls and other holes.
- At zero the hole is full and disappears, freeing its cells.
- Clear every cat before the timer runs out.

A hole's starting number always equals the number of cats of its colour on the board, so
there is no slack — every hole must eat exactly its own colour. This matches the original
and is what makes the puzzle tractable to verify.

## Layout

```
index.html          markup and overlays
styles.css          all styling
src/engine.js       the rules. No DOM, so tools/ can import it under Node
src/render.js       canvas drawing — board, cats, holes, effects
src/audio.js        synthesised sound, no asset files
src/main.js         game loop, input, HUD, save state
levels/levels.json  generated level data
tools/solver.mjs    BFS solver
tools/build-levels.mjs   level generator
tools/verify-levels.mjs  replays each level's solution through src/engine.js
```

## Levels

Levels 1 and 4 are transcribed cell-for-cell from screenshots of the original game. The
other 18 are generated by **reverse construction**: start from a cleared board and play
moves backwards, spawning cats into the cells each hole vacates. A level built this way is
solvable by definition, because the forward solution is the build sequence run in reverse.

Each candidate is then solved by BFS for its true minimum move count, and the generator keeps
the deepest candidate it can find for that slot. Every number in `levels.json` is a proven
shortest solution, not an estimate.

The solver exploits the capacity rule above: since a hole's capacity is always the live cat
count of its colour, capacity is derived rather than stored, and a position collapses to
(hole origins, alive-cat bitmask) — small enough to search exhaustively.

Rebuild the level set with:

```bash
node tools/build-levels.mjs
```

It takes several minutes and is deterministic — the same seeds produce the same levels.

The solver and the game engine are separate implementations of the same rules, so a drift
between them could "verify" a level that is actually unplayable. To rule that out:

```bash
node tools/verify-levels.mjs
```

This asks the solver for an actual move list per level and replays it through `src/engine.js`,
the code the game runs on, asserting it reaches a win. All 20 levels pass.

Difficulty, as proven shortest solutions: 2, 4, 7, 16, 7, 11, 11, 12, 14, 15, 14, 16, 19, 18,
18, 17, 19, 17, 19, 17. Level 4 is the spike because it is the original game's own level 4,
kept faithful rather than smoothed. The last third plateaus around 17–19 moves — reverse
construction struggles to push proven depth past that on a 7×7 board.

## Accessibility

Each colour carries a distinct glyph on the cat's belly (circle, heart, leaf, drop, star,
diamond, flower, square), so the board does not rely on hue alone. `prefers-reduced-motion`
is respected.

## Not built yet

This is the 20-level demo. The original's later-level systems are not implemented:
axis-locked and one-way holes, the edge trays seen from level 10 on, and the cages and
key-cats from level 66. See `PLAN.md` for what is known about each and what is still open.
